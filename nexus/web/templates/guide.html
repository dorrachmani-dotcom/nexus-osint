Beginner's guide

Nexus-OSINT collects open information from public sources, stores it locally on your machine, and (optionally) uses AI to summarise, translate, and rank it. Nothing leaves your computer except the searches you choose to run. This page explains every concept and walks you through your first investigation.

Quick start — 6 steps

  1. Add your keys (optional). Go to Settings and paste any API keys you have. Each key unlocks one more source or the AI analysis. No keys? The app still works with free RSS feeds — nothing crashes.
  2. Open a Case for your subject. On Cases, create a case (e.g. Tesla). In its Live feed tab add tracking words (e.g. Tesla, Elon Musk) — or give a one-line brief and let the AI set them up. Those words are searched across all your sources and drive the case's live feed.
  3. Run a scan. Press Manual scan on the Feed (or Scan now inside a case's Live-feed tab). The app fetches fresh items and saves them locally.
  4. Read the Feed. The Feed is the unified river of everything collected. Search the full history, filter by source, threat level, or date.
  5. Check ranked Intel. The Intel page scores items against your intelligence requirements so the most relevant rise to the top.
  6. Save to a Case & export. Bookmark important items, add notes, group them into a Case, and export a report when done.

Run a 100% local AI (no key, fully offline)

The AI part (summaries, translation, threat scoring) can run in three ways: a cloud service (Claude, Gemini, or ChatGPT — needs a paid API key), a free model on your own computer, or off entirely. The local option is the most private: the text it reads never leaves your machine. Here's how to set it up, step by step — no prior knowledge needed.

How it works — what actually happens behind the scenes

Ollama is a small AI server that runs quietly on your own computer at localhost:11434 — an address that only this machine can reach. When a scan finds a new item, Nexus hands the item's text to that local server, the model on your computer reads it, and hands back a summary, a threat score, a translation, and a disinformation flag. That whole round-trip stays inside your computer — no internet connection is used for the analysis, no account, no API key, and nothing about your subject is ever sent to Anthropic, Google, OpenAI, or anyone else.

It's the same pipeline the cloud providers use, with one swap: the “brain” is a model file on your disk instead of a service on the internet. Two built-in cost-savers still apply — a cheap local prefilter drops obvious noise before the model sees it, and a per-scan budget caps how many items are analysed at once — so even a modest laptop keeps up. Results are cached, so re-scanning never re-analyses the same item twice.

If Ollama isn't running when a scan starts, nothing breaks: collection, search and the feed keep working, analysis simply pauses for that scan and resumes automatically the next time the model is available. This is the same “graceful degradation” rule the whole app follows — a missing piece never causes a crash.

  1. Install Ollama. Ollama is a free, official app that runs AI models on your computer. Download it from ollama.com/download (there's a version for Windows, Mac and Linux). Install it like any other app. Once installed, it quietly runs in the background — you don't need to open anything.
  2. Turn it on in Nexus and download a model — no terminal. Go to Settings, and under AI provider choose "Local model (Ollama)", then press Apply. A short setup box appears: pick a model from the dropdown (a "model" is the actual AI brain) and click Download model. A progress bar fills as it downloads — a few gigabytes, but only once. You can leave the page; it keeps going. Not sure which? Keep the recommended gemma4:e4b; the table below maps models to computers.
  3. Confirm and you're done. Click Test connection — when it turns green, every scan from now on analyses items using your local model.
  4. That's it. From now on, every scan analyses items using your local model. No key, no bill, and nothing about what you're investigating is sent to any outside company.

Which model should I pick for my computer?

Models come in sizes measured in "B" (billions of parameters) — bigger = smarter but heavier. Rule of thumb: you need roughly the model's download size free in RAM (memory). A graphics card (GPU) makes it much faster but is not required — it also runs on the processor (CPU), just slower. To use one, run ollama pull <name>, then put the same name as OLLAMA_MODEL in .env (or keep the default).

Minimum requirements (what I recommend)

Bare minimum to run anything: 8 GB RAM, ~5 GB free disk per model, any 64-bit Windows / Mac / Linux. Works on CPU alone — no graphics card needed.

Recommended for comfortable use: 16 GB RAM, an SSD, and (optional but a big speed boost) a GPU with 6+ GB of memory. This runs the default Gemma 4 (E4B) smoothly.

Disk space: each model is a one-time download — roughly 2 GB (E2B), 4 GB (E4B), 9 GB (12B), 18 GB (26B), 22 GB (31B). You can delete models you don't use with ollama rm <name>.

Not sure? Start with the default gemma4:e4b. If it feels slow, switch down to gemma4:e2b; if you have power to spare, switch up to gemma4:12b. Changing model = one ollama pull + updating OLLAMA_MODEL.

If "Test connection" stays red: make sure Ollama is actually running (reinstall/relaunch it), then try again.

If it's amber ("model not downloaded"): repeat step 2 with the exact model name shown.

Is it slower than the cloud? Yes, especially without a powerful graphics card — but it's completely private and free. You can switch providers any time in Settings.

Add any API as a source (no coding)

Beyond the built-in sources, you can connect any public JSON API — a news API, a threat-intel feed, a government open-data endpoint — from the Sources page. Once added, it is scanned on every run like any built-in source.

  1. Let the AI set it up (easiest). If an AI backend is connected, paste a link to the API's documentation and/or an example of its JSON response, then press Draft the configuration. The AI works out how the API is called and where the content lives, and fills in the form for you to review.
  2. Or fill it in by hand. No AI connected? Enter the fields yourself: the base URL, the endpoint, how it authenticates, and the field mapping — which field in each result holds the text, title, link, author and date.
  3. Add a key if the API needs one. Paste it in the API-key box. Like every secret, it is saved to .env only — never the database, never shown back.
  4. Test, then save. Use the per-source Test button to do a live fetch and confirm items come back before it joins the next scan. You can disable or delete a source any time.

Graceful by design: a misconfigured or unreachable source simply returns nothing and is skipped — it never breaks a scan.

Sherlock — your in-app assistant

The friendly green detective in the bottom-right corner is Sherlock, a chat assistant powered by the same AI provider you set in Settings. Ask it how something works, ask questions about the data you've collected, or simply tell it what to do in plain English — it can carry the action out for you. (With no AI provider connected it still answers basic questions; the “do it for me” actions need a provider.)

Things you can ask Sherlock to do:

  • Run a scan — fetch fresh items now.
  • Search the feed — find items by keyword.
  • Open a case and add the matching items.
  • Generate a report (PDF/HTML) for a case.
  • Capture evidence — a timestamped screenshot of an item.
  • Add a watchlist term (keyword / wallet / phone / regex).
  • Add a requirement — a question that drives Intel ranking.
  • Write a case note.
  • Open a page in the app for you.

Example: “open a case on the Nightjar Group breach, add the related items, and make me a PDF.” Sherlock shows you exactly which actions it took, with links to the result.

Safe by design: Sherlock only ever performs constructive, local actions. It cannot delete anything, change your settings, API keys or AI provider, or send your data anywhere — even if you ask it to.

Transfer — carry your work to an offline computer

Many analysts keep two computers: one that goes online to collect, and a separate air-gapped machine — never connected to any network — where the sensitive analysis lives. The Transfer page moves your intelligence between them on a USB stick, with no network in between.

  1. On the online computer — Export. Save a single .nexusbundle file: everything, just one case, or only what's new since your last export (so a daily run produces just that day's items). Copy it to a USB stick.
  2. On the offline computer — Import. Plug in the stick and import the bundle. Every item appears instantly with its summary, translation, entities, relevance scores and evidence screenshots. Article links are kept for reference but, being offline, simply won't open — which is expected.

Safe by design: a bundle carries only collected open-source data and its analysis — never your API keys or settings, which stay on each machine. Re-importing the same bundle is harmless (items are matched by content, not duplicated), and every imported file is checked by the security scanner before anything is read.

Security center — stay in control of your data

A privacy tool should be auditable. The Security page gives you two fully local defences — both run on your machine and never phone home on their own.

  1. Outbound-traffic monitor. Every network connection the app makes is recorded and labelled as expected (an AI provider, a source you configured, or this computer) or unexpected. This is your honest answer to “is this tool sending my data somewhere it shouldn't?” You can download a plain-text audit report of this list to keep or hand to a reviewer.
  2. File scanner. Bringing in a file from a USB stick or the web? Upload it here first. It checks for executables disguised by their name (a “photo.png” that is really a program), booby-trapped archives (zip-slip paths, zip bombs), installers or scripts hidden inside archives, and macro-bearing Office documents — entirely on this machine.

Optional extra engines (graceful): if the clamscan antivirus is installed it is used automatically. VirusTotal is off by default — only if you set VIRUSTOTAL_API_KEY is a file's SHA-256 hash (never the file itself) looked up online. That hash lookup is the one and only part of the Security center that uses the network, and only when you opt in.

What the words mean

Source
A place information comes from — an RSS feed, a search engine, Reddit, Telegram, and so on. Most need an API key; RSS is free and always on. You can also add your own from any public JSON API.
Tracking words
The list of words a Case follows (its "word capsule"). Items mentioning any of them appear in the case's Live-feed tab, and the words are searched across all your sources on each scan.
Scan
The act of fetching new items from your sources. Scans only run when you ask for them — there is no background monitoring.
Threat level
An AI-assigned label (when AI is enabled) hinting at how security-relevant an item looks. Use it as a filter, not a verdict.
Requirement & relevance score
A requirement is a question you want answered (e.g. “What is the latest on Tesla?”). Each collected item is scored against it; higher score = more relevant. This is what powers the Intel ranking.
Case (investigation hub)
The single home for one subject. A case holds its tracking words (a live feed), its questions, your pinned items and notes, and sub-cases — all in one place — and exports the whole thing as a report.
